# cluster/integrate — 常开机制

**共同点：全部不含 LLM。** 编译器不会幻觉，先到先得不需要判断。

## 这里放什么

### 持续集成引擎

```
每 3-5 分钟:
  各节点 worktree 分支 → 合到集成分支 → 跑 verifyCommand (tsc --noEmit)
  错误按文件路径归属到节点 → 轮次边界注入回该节点
  归属不到任何领地的错误 → 升给协调层 (这本身就是"切错面"的信号)
```

**实测依据**：k=4 攒 19.4min 一次性合 → 460 个错 → 修 25.5min，集成代价 131%（修复段比并行段还长）。
本可以是 10 次 × 5 个。这是 big bang integration，软件工程五十年前就解决了的问题。

三个已知的坑，实现时别绕过去：
- **合并冲突不许让 agent 自己解。** 领地不重叠就不该冲突；真冲突 = 领地划错了，
  这是最有价值的告警，升上去，不是就地修补。
- **回灌只给属于你的错误。** 别把 460 条全塞给每个节点。归属靠 `路径 ∈ ownedPaths`，确定性。
- **不能打断节点。** 走轮次边界注入。

### claim 注册表

先到先得的文件/命名锁。写文件，不过 LLM。零 token、零延迟、结果确定。

**实测依据**：k=2 建出 `org/` + `peopleorg/` 两套同样的东西；k=4 又多出 `hr/` + `shared/`；
同名重复文件 k=1 有 3 个（正常分层同名），k=2 有 24 个，k=4 有 28 个。

与 `scheduler/readySet.ts` 里那个领地重叠检测的分工：那个管**规划期**（图不合法就别开跑），
claim 注册表管**运行期**（第二个节点想建 `org/` 时拿到"已被 node-a 占了，用它的"，
而不是自己另起一个 `peopleorg/`）。

## 边界

- ❌ 不含 LLM。这一层任何地方需要"判断一下"都是设计错了——把判断升给上层。
- ❌ 不许出现业务语汇。它只认路径、分支、退出码。
